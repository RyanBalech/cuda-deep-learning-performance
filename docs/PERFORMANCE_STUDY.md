# Performance Study Protocol

## Research question
How do memory access patterns, shared-memory tiling, and kernel fusion change core deep-learning operator performance across workload sizes?

## Rules
1. Establish correctness against a reference before timing.
2. Use CUDA events and explicit synchronization for GPU timing.
3. Warm up before measured trials.
4. Record shapes, dtype, trial count, GPU, CUDA/driver versions and compiler flags.
5. Separate kernel-only latency from transfer-inclusive latency.
6. Report multiple workload sizes, not one favorable case.
7. Treat cuBLAS/PyTorch as optimized library baselines, not expected targets for hand-written kernels.
8. Keep slower optimizations when they reveal a bottleneck.

No performance number is published until generated by a reproducible run on identified hardware.
